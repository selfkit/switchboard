## 逐项证据与修复建议

### A01：多租户公共后缀不能作为凭据信任边界

位置：[Rust 站点判定](/Users/macbookpro/Desktop/tan/code/me/switchboard/src-tauri/src/session.rs:705)、[JS 帧来源判定](/Users/macbookpro/Desktop/tan/code/me/switchboard/src-tauri/src/adapter.rs:118)。

`site_of()` / `site()` 用域名末尾两段或三段推断站点，没有公共后缀表。例如 `customer-a.github.io` 和 `customer-b.github.io` 均被折叠为 `github.io`。两个租户可以由不同主体控制。

触发条件：用户配置多租户托管域名为登录站；在自动填充许可期内跳转到另一个租户，或登录页面嵌有另一个租户控制的 iframe。旧 agent 向各帧询问输入框，由先认领的帧接收明文值，错误的同站检查放行恶意租户。

隔离复现直接执行生产 agent，恶意租户 iframe 收到了虚构测试密码；Rust `fill_allowed(https://customer-a.github.io/login, https://customer-b.github.io/)` 返回 `true`。未向真实网站发送凭据。

修复：凭据默认绑定明确的 origin；必要 SSO 站点使用显式授权列表。需要可注册域名判定时，使用包含 private suffix 的公共后缀表，并在 Rust、旧 agent 和新 agent 的相关边界统一规则。公共后缀表本身也不意味着企业所有子域都应自动获得密码。另一个需收紧的策略是手动填充的 `same_host()`：目前忽略协议和端口，HTTPS 登录凭据可以被手动填入 HTTP 页面。

验收：不同 `github.io` 租户不得互领凭据；合法 SSO 只在明确授权后通过；HTTP 降级与跨端口行为有明确限制。

### A02：旧版指认完成后，没有锁定原文档和原页签

位置：[回调与立即填写](/Users/macbookpro/Desktop/tan/code/me/switchboard/src-tauri/src/lib.rs:1706)、[指认状态](/Users/macbookpro/Desktop/tan/code/me/switchboard/src-tauri/src/session.rs:1967)、[导航处理](/Users/macbookpro/Desktop/tan/code/me/switchboard/src-tauri/src/session.rs:848)、[远端权限](/Users/macbookpro/Desktop/tan/code/me/switchboard/src-tauri/capabilities/session.json:7)。

`report_picked_selectors()` 只根据调用 WebView 的 label 查 `picking` 布尔标记。该标记没有 origin、文档 nonce 或有效期；导航只使新绑定任务失效，没有清除旧版指认。回调保存配置后，调用 `eval_active()`，目标是当时的活动页签，未必是上报结果的页签。

可达场景一：在可信页面开始指认，随后同一页签跳转到其他站点。新站点仍获得 session-report 权限，可在旧标记保留期间上报选择器并触发明文填写。场景二：A 页签回调延迟到达，而用户已切换到 B 页签，密码被交给 B 的页面脚本。还会将不可信选择器写入平台适配配置。

证据为代码调用链，尚未运行完整原生 IPC 攻击复现。修复应将指认绑定到账号、WebView label、可信 origin、文档 nonce 和到期时间；导航/关闭/锁定即取消；执行前用原生 URL 重新核验；只向发起指认的 WebView 填写。仅更换 `eval_active()` 仍不足以解决跨导航问题。

验收：指认中跨站导航、切页签、锁定、超时和迟到回调均不能触发错误目标填写，也不能保存无效配置。

### A03：保活锁定与新窗口创建之间缺少统一门禁

位置：[锁定保留保活会话](/Users/macbookpro/Desktop/tan/code/me/switchboard/src-tauri/src/lib.rs:324)、[新窗口入口](/Users/macbookpro/Desktop/tan/code/me/switchboard/src-tauri/src/session.rs:821)、[独立弹窗](/Users/macbookpro/Desktop/tan/code/me/switchboard/src-tauri/src/session.rs:931)、[布局显示状态](/Users/macbookpro/Desktop/tan/code/me/switchboard/src-tauri/src/session.rs:389)。

锁库会隐藏保活页面，但这些页面继续运行。`on_new_window`、`open_popup_window()` 和页面触发的 `open_tab_with()` 不检查账号库锁定状态。独立弹窗按默认可见状态创建，且布局同步明确跳过 `external` 窗口。

普通子页签还存在显示状态不一致：`add_child()` 创建原生 WebView 后，应用侧将 `shown` 初始化为 `false`，却没有先调用 `hide()`；所用 Wry 0.55.1 的可见性默认值为 `true`。锁定后 `want == false`，布局逻辑认为它已经隐藏，可能不执行隐藏操作。

触发条件是保活页面在锁定后产生新窗口请求，或者此前排队的创建请求在锁定后完成。结果可能是新的已登录页面出现在解锁界面之上或独立窗口中。此项有直接代码证据，**尚未在原生 WKWebView/WebView2 中复现**，需要结合浏览器弹窗策略和线程时序验证。

修复：将锁定状态作为所有新窗口路径的后端门禁；窗口/子 WebView 先隐藏创建，注册完成后再按当前授权状态显示；异步创建完成时再次验证锁状态及账号是否仍存在，失败时销毁未登记对象。保活可以继续，创建可见页面应等解锁后再执行。

验收：手动锁、自动锁、系统锁屏期间定时开窗及并发开窗，均不得出现账号页面；锁定与创建竞争也不得留下未登记窗口。

### A04：页面可自行维持活动时间戳

位置：[无来源校验的活动消息](/Users/macbookpro/Desktop/tan/code/me/switchboard/src-tauri/src/adapter.rs:273)、[后端活动命令](/Users/macbookpro/Desktop/tan/code/me/switchboard/src-tauri/src/lib.rs:502)、[远端可调用权限](/Users/macbookpro/Desktop/tan/code/me/switchboard/src-tauri/permissions/session-report.toml:13)。

顶层 agent 收到 `{__sb: 1, t: 'activity'}` 即调用 `reportActivity()`，没有核验发送帧来源，也不要求真实输入事件。更直接的路径是外部顶层页面自行调用获准的 `touch_activity` IPC。

隔离复现中，不相关 iframe 在没有任何用户操作的情况下成功触发 `touch_activity`。在空闲超时前持续发送即可让自动锁定永不达到阈值；现有“已经超时就不续命”只能防止超时后复活，不能阻止持续续期。保活计时也会被干扰。

修复：自动锁定依据原生可信输入或其他不可由远端 JS 任意写入的活动来源。仅校验 message origin 不够，因为顶层第三方页面本身也能调用该命令；仅在同一 JS 世界中增加一个 token 同样不构成可靠边界。

验收：任意第三方页面或 iframe 周期发送消息/IPC，仍应在无真实操作时按设定时间锁定。

### A05：HTTP 自建站的新字段绑定启动失败

位置：[脚本开头](/Users/macbookpro/Desktop/tan/code/me/switchboard/src-tauri/src/binding-agent.js:7)。

初始化立即执行 `crypto.randomUUID()`。该 API 需要安全上下文，普通 HTTP 局域网 IP 或非 localhost 域名不满足条件，而应用允许此类自建站地址。[Web Crypto 接口定义](https://w3c.github.io/webcrypto/#Crypto-interface) 为 `randomUUID` 标注了 `SecureContext`。

在保留 `crypto.getRandomValues`、不提供 `randomUUID` 的 VM 中执行原生产脚本，直接抛出 `TypeError: crypto.randomUUID is not a function`，后续代理初始化停止。因此 HTTP 站点可能正常打开，但指认与执行绑定不可用。此复现验证脚本故障，未替代原生 HTTP WebView 测试；localhost 与 HTTPS 不应一概判为受影响。

修复：为非安全上下文采用 `crypto.getRandomValues` 生成随机标识，或由后端分配；不可用 `Math.random` 替代安全标识。增加 HTTP LAN、HTTP localhost、HTTPS 三类环境验收。

### A06：两分钟时间窗不能识别登录表单

位置：[旧版查找和赋值](/Users/macbookpro/Desktop/tan/code/me/switchboard/src-tauri/src/adapter.rs:289)、[自动填充触发](/Users/macbookpro/Desktop/tan/code/me/switchboard/src-tauri/src/session.rs:862)。

旧版 agent 只按选择器查找可见的账号/密码框，然后赋值，没有排除 `autocomplete="new-password"`，也没有保护已填内容。打开或刷新后两分钟内进入同站改密码/注册页，默认或过宽选择器仍可命中。

隔离复现已将虚构旧密码写入明确标注 `new-password` 的输入框。README 对“不会填写修改密码框”的承诺因此不成立。新字段绑定中的页面条件和已有值保护不能保护仍启用旧模式的账号。

修复：自动填写需要明确登录页面及控件条件，排除新密码/只读/禁用控件，默认不覆盖已有内容；扩展现有 agent 回归测试，覆盖登录页、改密码页和已输入表单。

### A07：备份可以通过预检，却在替换当前库后无法使用

位置：[导入预检及替换](/Users/macbookpro/Desktop/tan/code/me/switchboard/src-tauri/src/lib.rs:1830)、[账号计数](/Users/macbookpro/Desktop/tan/code/me/switchboard/src-tauri/src/db.rs:334)。

导入只检查密码可打开、`SELECT count(*) FROM accounts` 成功，读取 owner 失败被忽略。没有在替换之前验证完整 schema、记录可读性或迁移是否成功。

使用临时 SQLCipher 数据库，仅建立 `accounts(id TEXT PRIMARY KEY)` 并插入一条虚构记录，生产 `count_accounts()` 返回 `Ok(1)`；随后生产 `db::prepare()` 报错 `no such column: platform`。该备份可通过当前预检，但下次解锁准备数据库会失败。

现有实现会保留 `.replaced-*` 旧库，因此这不是已经证明的永久数据丢失；问题是正常库已经被换下，用户需要手动恢复，应用内恢复路径又要求可使用当前库。

修复：先复制到临时文件，在临时副本上完成 SQLCipher/SQLite 完整性检查、schema/版本校验、迁移、账号和绑定读取验证，全部成功后再交换文件。保留现有归档和失败回滚，避免验证过程改动用户选中的备份。

验收：缺列、坏记录、迁移失败、损坏页面、错误密码等备份都应在当前库和当前会话被替换之前被拒绝；合法旧版备份迁移后可用。

### A08：同一页签的并发下载会串文件路径

位置：[下载开始和完成回调](/Users/macbookpro/Desktop/tan/code/me/switchboard/src-tauri/src/session.rs:628)。

每个 WebView 只保存一个 `Arc<Mutex<PathBuf>> last`。A 开始后 B 开始，B 覆盖该变量；A 完成时 `Finished { success, .. }` 忽略事件的 URL/路径，读取的已是 B 的路径。

结果包括错误完成通知、定位错误文件，开启“每次询问”时还可能尝试移动尚未完成的 B。静态事件序列足以确定身份关联错误，但实际下载中途移动的文件系统后果未实机验证。

修复：按每次下载的稳定标识维护状态，优先使用原生完成事件路径；macOS 不返回路径时需设计可处理并发及重复 URL 的关联方式，不能用单个“最后下载”变量。加入 A/B 交错完成和同 URL 重复下载测试。

### A09：下载完成处理只在会话页存活

位置：[下载订阅](/Users/macbookpro/Desktop/tan/code/me/switchboard/src/screens/SessionsPage.tsx:98)、[后端仅发送事件](/Users/macbookpro/Desktop/tan/code/me/switchboard/src-tauri/src/session.rs:639)。

下载监听器在 `SessionsPage` 的 effect 中注册，页面卸载时取消。下载可以继续在后台进行，但用户进入账号库或设置后完成的下载，没有全局监听者，也没有待处理队列。返回会话页不会重放事件，“每次下载都问保存到哪”会漏弹，完成消息也丢失。

修复：在应用根层维护下载状态及持久到页面切换之外的完成队列；解锁后统一处理另存请求，提供下载记录。验收覆盖切页面、锁定、连续完成多个下载，避免多个保存对话框互相覆盖。

### A10：SPA 的当前路由没有进入会话状态

位置：[last_url 更新](/Users/macbookpro/Desktop/tan/code/me/switchboard/src-tauri/src/session.rs:854)、[刷新读取旧地址](/Users/macbookpro/Desktop/tan/code/me/switchboard/src-tauri/src/session.rs:1954)、[区域恢复](/Users/macbookpro/Desktop/tan/code/me/switchboard/src-tauri/src/session.rs:1761)、[工具栏读取地址](/Users/macbookpro/Desktop/tan/code/me/switchboard/src/screens/SessionsPage.tsx:647)。

`last_url` 主要在整页加载完成时更新。SPA 的 `pushState`、`replaceState` 和 hash 路由切换不产生对应的整页加载完成事件。新字段绑定虽然观察自身路由变化，却没有同步这份会话 URL。

因此从 `/home` 进入 `/projects/123` 后，工具栏刷新和区域中断后的恢复可能回到 `/home`；复制地址和系统浏览器打开同样可能使用旧路由。保活路径已主动查询原生当前 URL，说明该场景在代码中已有先例，但普通刷新尚未统一。

修复：维护可靠的原生当前 URL，主动操作时再次查询；断网切断前记录当时路由。不能在原生回调事件线程中同步查询导致自等待。验收覆盖 history 和 hash 两类 SPA，并检查真实地址与工具栏一致。

### A11：快捷切换没有覆盖账号网页焦点

位置：[主窗口按键监听](/Users/macbookpro/Desktop/tan/code/me/switchboard/src/App.tsx:398)、[网页内快捷键代理](/Users/macbookpro/Desktop/tan/code/me/switchboard/src-tauri/src/adapter.rs:461)。

Cmd/Ctrl+K 仅监听主 React WebView 的 `window.keydown`。账号页面是独立的原生子 WebView，其 DOM 按键不会冒泡给 React 主窗口；页面代理处理了查找快捷键，却没有 K 的转发，代码中也未找到对应原生菜单加速键。

用户正在账号网页输入时，快捷切换缺少处理路径；先点击主界面再按可能恢复。此为静态焦点边界分析，需 macOS/Windows 分别验证与系统/站点快捷键的交互。

修复：使用合适的应用级原生快捷键，或将网页的特定快捷键信号限制为“打开切换面板”这一 UI 动作；不扩大远端读取账号权限。覆盖输入框、iframe、独立弹窗焦点。
